# 最新 Chat 角色与十九项逐项独立核对规则

## 一、这份文件的身份

用户已经授权采用“方案一”：把最新 Chat 调整为按十九项逐项读取中性原始证据、独立判断的审查者。

本目录只服务于这一次十九项独立核对。它不是新的业务阶段，不是新的问题总账，不是十九项结论，也不产生修复、重新计算、采用输入、建立客观交易链或正式交易分析权限。

## 二、最新 Chat 的角色

最新 Chat 每次只核对十九项中的一项。

对每一项，必须先阅读该项单独的中性原始证据包，再根据实际读到的证据作出独立判断。不得先看当前 Work 已经形成的十九项答案，也不得接续原“交易复盘接管 Chat”没有完成的十九项文字。

当前 Work 的以下两份候选不在本中性证据分支中，也不得在十九项独立判断全部完成以前读取：

- `01_十九项逐项证据核对与实际影响_待用户核对.md`
- `02_用户白话结论_待用户核对.md`

## 三、一次只处理一项

1. 用户或当前 Work 每次只指定一个编号和一个固定提交。
2. 最新 Chat 只打开本轮指定的证据包，以及证据包明确点名的必要原始位置。
3. 不提前读取下一项，不把本项结论复制到其他编号。
4. 本项回报完成后立即停止，等待下一项。
5. 十九项全部独立判断完成以后，才允许公开当前 Work 的对应结论并逐项交叉核验。

## 四、证据身份必须分开

证据包可能同时包含以下内容，最新 Chat 必须分开判断：

- 用户直接说过的话；
- 当时 Chat 或其他人工智能提出的理解、方案或限制；
- 用户消息中转贴的 Codex／脚本执行回报；
- 当前 Work 对文件本体进行的只读结构核验记录；
- 阶段一、阶段三和后来查证成果中已经冻结或验收的历史记录。

“用户提出需要什么”不等于交易所事实已经存在；“当时人工智能认为可以怎样做”不等于方案已经正确执行；“Codex 报告完成”不等于获得交易所级绝对证明；“冻结成果中写着缺口”也不是本轮必须照抄的答案。最新 Chat 必须把这些材料互相核对后再判断。

## 五、固定判断标准

每项都要区分以下四个证据等级：

1. **权威原始事实**：由对应时期的交易所原始记录或能够直接核验的原始对象证明。
2. **可以确定计算或连接的结果**：原始事实齐全，按照固定规则可以唯一得出。
3. **有限估算、用户回忆或代理证据**：能够满足部分理解需要，但不能冒充精确权威事实。
4. **仍然未知或超出固定证据范围**：现有证据不能可靠决定。

不能把“没有百分之百精确”自动写成“完全不能用”，也不能把“用户有解释或存在历史算法”自动写成“交易所权威证明已经齐全”。

## 六、每一项必须回答的内容

请用普通中文回答：

1. 本轮实际打开并完整读到了哪些文件或哪些证据段；有无打不开、截断或无法验证的部分。
2. 用户在历史原话中对这一项真正要求什么。
3. 历史人工智能或旧工程提出过什么处理办法；这些内容属于方案、执行回报，还是实际可验证事实。
4. 现有材料已经直接证明了什么。
5. 现有材料仍没有直接证明什么。
6. **从严格事实证明看，这一项是否仍存在缺口。**只能回答“仍存在”“已经解除”或“现有证据不足以判断”，并说明理由。
7. **从用户建立并理解一百三十六笔客观交易链的实际需要看，现有证据和有限方法是否已经足够。**可以回答“足够”“部分足够”“不足”或“现有证据不足以判断”，但必须说明允许做到什么、必须保留什么限制。
8. 这一项会怎样具体影响将来的一百三十六笔客观交易链：影响哪些字段、关系、标注或解释；不能只写“有风险”。
9. 明确本项不能顺手处理哪些相邻事项。

## 七、严格禁止

本轮不得：

- 读取或比较当前 Work 的十九项结论候选；
- 读取原“交易复盘接管 Chat”的未完成十九项答案；
- 修改、创建、提交或上传任何文件；
- 改写阶段一、阶段二、阶段三或后来查证成果；
- 修改 04A、04B 或项目履历；
- 修复、重新计算或正式采用任何材料；
- 建立客观交易链或一百三十六笔交易链；
- 开始正式交易分析；
- 把本项判断自动推广到其他十八项；
- 因为历史冻结记录写了“缺口”就直接照抄，也不得因为用户认为历史材料可能足够就预先判定缺口已经解除。

## 八、停止位置

每次完成指定一项的独立判断以后停止。当前 Work 只保存最新 Chat 的原始回报，不在十九项全部完成以前向它公开自己的答案。
