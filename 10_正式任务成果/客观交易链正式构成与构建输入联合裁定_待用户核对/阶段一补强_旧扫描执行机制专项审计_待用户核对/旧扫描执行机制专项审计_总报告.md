## A. 审计结论摘要

### A1. 总结论

对本专项审计的核心问题，答案是：**NO。旧双向扫描不能证明“不存在共同遗漏”。** 全局证明能力止于 L2，只有选定消息和定点范围局部达到 L3，L4 未建立。

历史证据能够证明两次正式复扫都做到了以下两件事：

1. 对冻结来源清单中的 10,534 个源对象进行了枚举、身份登记或通用处置（L1）；
2. 扫描程序读取并解析了 W01–W04 共 1,518 条聊天消息的完整文本（L2）。

历史证据不能证明以下两件事：

1. 1,518 条消息的完整正文全部、无截断地暴露给模型并由模型逐条阅读（L3）；
2. 每条消息中的每个最小语义单元均被拆分，并留下“相关 / 不相关 / UNKNOWN / 非 USER / 重复 / 已归并”等闭合处置记录（L4）。

因此，“程序读取了全部消息”成立；“模型完整看过全部消息”不成立为已证明事实；“全部业务语义都已经逐单元处置”没有证明。第一遍的 34 个 HIST、第二遍的 25 条 REV 链和 83 个最终节点，都是对选中证据的可追溯整理，不能作为未选中消息或未命中语义均已被排除的反向证明。

PRE-K01 original 的实际执行更窄：它主要通过已知术语、已知对象、已知路径、特定 ID 和选定文件区间进行目标式检索与核验。它没有建立 10,534 个对象或 1,518 条消息的闭合语义分母。

Stage1-A1 同样是“程序全读 + 关键词/正则召回 + 预览/目标区间暴露 + 人工归纳”的组合。虽然其机器索引为 1,518 条消息生成了 `CHAT_MESSAGE_DISPOSITION`，但这些记录全部被程序统一标记为 `RELEVANT_STAGE1_EVIDENCE`，并非由逐消息、逐最小语义单元的模型审阅形成，故不能把它提升为 L4 证明。

### A2. 对“完整性”的最终裁定

| 证明对象 | 裁定 | 能证明的最高层级 | 不能证明的部分 |
|---|---|---:|---|
| SOURCE COVERAGE | PROVEN | L1 | 10,534 个对象的全部业务语义已读、已理解 |
| MESSAGE COVERAGE | PARTIALLY_PROVEN | L2 | 全部消息完整暴露给模型；全部语义已处置 |
| AUTHORSHIP COVERAGE | PARTIALLY_PROVEN | L2 + 部分 L3 | 混合消息内部每个 USER / AI span 均独立拆分和处置 |
| ENGINEERING OBJECT COVERAGE | PARTIALLY_PROVEN | L1 + 选中对象 L2/L3 | 独立发现且语义穷尽全部阶段、目录、上下游和文件关系 |
| BUSINESS SEMANTIC COVERAGE | NOT_PROVEN | 选中证据局部 L3 | 全部 1,518 条消息的闭合业务语义分母 |
| MINIMAL SEMANTIC UNIT COVERAGE | NOT_PROVEN | 无 L4 证明 | 一条消息内多语义单元的穷尽拆分与逐项处置 |
| TRADING TERMINOLOGY COVERAGE | NOT_PROVEN | 固定词表的命中检查 | 交易语义词族的封闭全集及逐词处置 |

### A3. NMC-001 / NMC-002 的审计结论

NMC-001“交易、账户与合约身份”和 NMC-002“保证金、杠杆与强平风险状态”并非来自新资料。二者的原始语义已经存在于 W01 的旧聊天原文中。两遍扫描程序都读取过对应消息，且两遍历史工具输出都把对应完整 USER 原文实际显示给了模型。但两遍扫描都没有留下逐消息/逐语义单元的闭合处置账，因此“模型实际看到过”仍没有转化为“被正式列为独立组件或完整事实”。“两遍因为从未看到原文而漏检”与执行证据矛盾。

可确认的机制原因是：固定词表、命中结果限额、正文预览、目标式区间读取，以及最终候选/事实/链条的硬编码选取，没有配套的未命中消息处置分母。确切的认知性遗漏原因没有历史记录，必须保持 UNKNOWN。不能事后断言某一个词、一次截断或某一次模型判断单独造成遗漏。

## B. 审计口径、范围与证明等级

### B1. 四级证明口径

| 等级 | 本审计采用的严格定义 | 典型可接受证据 |
|---|---|---|
| L1 来源已枚举 | 能证明来源对象进入了名单、快照或枚举集合 | 路径清单、对象 ID、计数、哈希、冻结快照 |
| L2 程序已全文读取 | 能证明程序对对象完整字节/文本执行了读取或解析 | `read_text` / `read_bytes`、解析器输入、完整哈希 |

| L4 全部语义单元已处置 | 能证明每个最小语义单元都有明确、可追溯的处置状态 | 闭合分母、逐 span/逐 unit 记录、计数对账、无遗漏校验 |

L1 不能自动推出 L2；L2 不能推出 L3；L3 也不能自动推出 L4。尤其是：脚本在内存中读取完整文件，只能直接证明 L2；如果工具只把摘要、首尾预览、关键词命中或截断输出返回模型，就不能声称 L3。

## C. 四套历史执行机制还原

### C1. PRE-K01 original

实际执行管线：

1. 从已知的 K01/PRE-K01 工作区、恢复材料、报告、manifest、CSV/JSON/Markdown 和特定对象路径进入；
2. 使用 `rg` 搜索已知术语、特征串、任务 ID、文件名或路径；
3. 使用 `sed`、`nl`、`jq`、Ruby 等读取选定文件或选定行区间；
4. 对已命中的材料做定点核验并形成结论。

该过程没有建立全源对象分母，也没有建立 W01–W04 1,518 条消息的逐消息处置账。它对部分选定文件可达到 L2，对模型实际收到的定点输出可达到局部 L3；没有全局 L1、全局 L3 或 L4 证明。

### C2. 第一遍正向扫描

实际管线：

1. `k01_pass1_parse_chats.py` 对 W01–W04 原始 Markdown 使用完整文本读取；W04 按当时边界截取至指定历史范围；程序解析出 1,518 条消息，并保存完整 `content`、行号、字符/字节信息和 SHA-256；
2. 对 770 个 Prompt 容器输出约 180 字符预览，按 200 条一组显示；由正则和人工集合进行 USER / mixed / uncertain / pure-non-user 分类；
3. 对全部消息运行固定 Purpose 2 关键词检索，但每个词只显示前 15 个命中、约 260 字符预览；USER 原文词检索每词只显示前 12 个命中、约 400 字符预览；另有正则检索显示约 500 字符预览；
4. 对工程对象使用文件树、文件名正则、已知对象名和已知路径模式召回；
5. 渲染脚本手工写入 19 个候选和 34 个 `reqs`/HIST 条目，并从指定消息或指定对象抽取证据；
6. 验证器检查条目数、唯一性、指针、文件存在性等结构条件，没有验证未命中消息的语义处置完整性。

第一遍的程序读取证明 L2；关键词输出、预览和定点区间只能证明部分 L3；34 个 HIST 是选择结果，不是 1,518 条消息的 L4 处置账。

### C3. 第二遍反向扫描

实际聊天反扫管线：

1. 解析器以字节方式完整读取 W01–W04，并按消息倒序建立 1,518 条记录；
2. 为 Prompt/Response 生成摘要文件、特征或 outline，而不是把所有原始正文直接无损暴露给模型；
3. W04 Prompt 尝试按 1–450、451–900、901–1350、1351–1800 行输出，但工具结果发生截断；W03/W02/W01 的完整 Prompt 文件也没有形成全部、无截断的模型暴露证明；
4. Response outline 实际显示 W04 的 91 条、W03 的前 110 条、W02 的前 35 条，W01 没有形成全 Response outline 的显示记录；合计只能给出 236 个 AI Response 容器的 outline 暴露下限，且 outline 不是全文；
5. 后续使用目标式 `sed`/检索读取选定区间；
6. 构建脚本手工写入 25 条反向证据链和 84 个、最终校正为 83 个来源节点，再用相似度/字面匹配定位指定证据片段；
7. 最终源 JSONL 记录的是 10,534 个源对象的通用处置，不是 1,518 条消息或全部语义单元的 Purpose 2 处置账。

W04 截止参数存在一行实现差异：第二遍 parser 使用 `--max-line 25709`，第一遍和 Stage1 的部分脚本处理前 25,710 行/报告最大业务行 25,710。三者消息分母仍同为 W04 186 条，说明该差异没有形成新增消息，但不能声称三套实现的截止参数逐字一致。

第二遍聊天子执行最初封版为 25 链/84 节点；后续根任务删除一个重复 G 节点并修订为最终 25/83。最终修复没有可验证的精确模型快照/推理档，不能把最终 83 节点全部归功于原先 `gpt-5.6-sol/ultra` 聊天子执行单元。

实际工程对象反扫管线：

1. 独立枚举当前文件树并对照冻结的 10,534 对象快照和哈希；
2. 读取旧救援审计报告、ledger、阶段正式成果登记和若干已知目录；
3. 使用硬编码阶段缩写/目录名列表、选定 xlsx 路径、前缀规格和关键词检索；
4. 对可支持文本/JSON/CSV/OOXML 做格式级读取或校验；
5. 为 10,534 个对象生成通用覆盖记录，并对选定对象建立更具体的 83 个来源节点。

因此，第二遍确实有“方向倒序”和独立产物，但“反向”不等于“逐语义单元穷尽”。它证明 L2 和部分 L3，不证明 L4。

### C4. Stage1-A1

实际管线：

1. Ruby/脚本完整读取聊天文件并用固定正则进行类别计数、头尾预览和消息摘要；
2. 输出 NOT-candidate 的 head 340 / tail 140 预览，以及部分 W01 USER 的 head 420 / tail 160 预览；相关工具输出存在截断；
3. 使用固定词组和正则检索历史聊天，随后读取 W01 的指定大行段；大行段输出也发生截断；
4. 对 NMC 使用明确预设的关键词组搜索，例如“杠杆、保证金、强平价、爆仓价、账户类型、合约类型、逐仓、全仓、现货账户、资金账户、期权账户、未成交、撤单、取消委托、下单尝试、开仓尝试”，再定点读取 W01 行段；
5. 组件构建脚本将 NMC-001/NMC-002 与指定证据串写入最终组件；
6. A1 曾运行一项相关性诊断：规则把 W02、W03、W04 直接归为相关（条件包含 `$w ne "W01"`），把 W01 第 83 条起直接归为相关，W01 前 82 条才依赖关键词/邻接；该诊断得到 1,518 条全相关；
7. 最终机器索引生成器没有把上述诊断结果逐条传入 disposition，而是在分别生成 W01、W02、W03、W04 记录时直接把 `relevance_disposition` 固定写为 `RELEVANT_STAGE1_EVIDENCE`。

这证明 A1 的发现不是随机猜测，而是由旧聊天中的真实语句支持；同时也证明 A1 不是“模型无预设地逐条全文阅读全部 1,518 条消息并逐最小语义单元处置”。其最高可证明能力是 L2 + 关键词命中/目标区间的部分 L3；诊断规则的直接归类方式、诊断结果未逐条进入最终生成器以及最终字段的固定写入，共同说明统一消息标签不构成 L4。

据此，Stage1 正式报告第 34–35 行“相关性处置 1518/1518”、第 41 行“A1先完整处置原始Chat”、第 178 行把 1518/1518 列作完成条件等自述，必须在本机制审计中降级解释为：**消息身份、边界、正文哈希记录 1518/1518；业务相关性是程序固定标签，不是逐消息模型语义裁定。** 这是证明强度更正，不改变 Stage1 的 1,518、770/748、41/35、32 组件或 4 个 NMC 等数量终值。

## D. Q1–Q15 逐题回答

### Q1. 第一遍 Purpose 2 是否真的处理了 1,518 条消息？

结论：**程序层面是，语义完整性层面否。**

1,518 条消息均由解析程序完整读入并进入固定关键词检索，故 L2 成立。但模型主要收到 Prompt 预览、每词限量命中、正则命中和定点片段；不存在 1,518 条逐消息的相关/不相关/UNKNOWN 处置记录。因此不能声称 1,518 条均完成模型全文阅读或 Purpose 2 语义处置。

### Q2. 第二遍是否真的反向处理了 1,518 条消息？

结论：**程序倒序解析是，模型逐条全文反扫和语义闭合否。**

反扫程序确实按倒序创建了 1,518 条记录，故 L2 成立。模型看到的是 prompt 特征、response outline、目标区间和选定证据，且发生输出截断。25 条 REV 链/83 个节点不是 1,518 条消息的逐条 disposition。

### Q3. 四套机制实际读取了哪些对象类型？

| 机制 | 实际读取对象 |
|---|---|
| PRE-K01 original | 已知报告、恢复资料、manifest、CSV/JSON/Markdown、选定源码/脚本、特定工作簿/目录、特定聊天片段 |
| 第一遍 | W01–W04 完整聊天文本；10,534 对象的快照/元数据；选定文本、JSON/CSV、OOXML/工作簿、目录/文件树；已知工程对象 |
| 第二遍 | W01–W04 完整聊天字节；prompt/response 派生摘要；冻结源快照与当前文件树；旧审计报告/ledger；支持格式的通用校验；选定阶段资产 |
| Stage1-A1 | W01–W04 聊天文本；正则/关键词结果；W01 指定区间；Stage1 选定的 41 项资产/51 个路径及相关旧结果 |

“读取对象”在表中同时包含 L1、L2 和局部 L3 对象，不应被混写为“全部模型全文阅读”。

### Q4. 是否采用分块；如何分块；是否存在截断？

结论：**采用了分组、预览、outline 和定点区间，多处存在截断；没有形成无缺口的 L3 分块闭合证明。**

- 第一遍：Prompt 预览按 200 条分组；正文约 180 字符；前两批历史工具输出明确发生截断。固定词命中每词限 12/15 条，预览约 260/400/500 字符，部分关键词输出也发生截断。
- 第二遍：W04 Prompt 尝试四个连续行块，但返回结果记录为截断；其他文件以特征和 outline 为主。Response outline 只显示 W04 91、W03 110、W02 35、W01 0 条的可确认下限。
- Stage1-A1：head/tail 预览和大行段 `sed` 输出均出现截断警告。
- PRE-K01 original：无全局分块计划，以临时 `sed`/`nl`/`jq` 选段为主。

### Q6. 第一遍 34 个 HIST 的实际生成管线是什么？
