# 136笔客观交易链｜输入、组装与防错闭合矩阵候选

更新日期：2026-09-10

## 0．文件身份

本文件是《136笔客观交易链建立实施方案候选｜重新起草版》的组成部分，不是第二套方案，也不是新的问题总账。

它只把主方案中必须逐项闭合的内容放在一起，避免执行者临场决定：

- 三十二项组成；
- 九十四项能力的闭合办法；
- 四十四项输入候选的生产角色；
- 十九项严格缺口的字段处理；
- 阶段三后查证形成的十六项发现；
- 三项重新计算；
- 固定分母、来源合并和验收关系。

本文件仍是候选。下列“建议采用”不是用户已经作出的正式采用决定。

四十四项的完整路径、字节数、SHA-256、工作表、行列、JSON指针、排除字段、组成和能力映射，不在这里复制第二套。唯一技术来源是正式阶段三机器总账中的S3INPUT-01至S3INPUT-44。执行时必须从固定版本机器总账读取并核验，不能依据本文件中的简称猜选区。

## 2．九十四项能力怎样闭合

九十四项能力继续沿用阶段三机器总账中的原编号、原描述、原状态和原输入关系，不再建立新的能力编号。

未来执行时，从机器总账逐项生成一张运行表，每项至少含：

| 字段 | 含义 |
|---|---|
| 能力编号 | 沿用阶段三原编号 |
| 所属组成 | 对应C01至C32 |
| 阶段三裁定 | 已支持、严格缺口、边界或新增候选 |
| 适用粒度 | 全局、账户、周期、交易、对象、字段、关系或非客观边界 |
| 获准输入 | 对应S3INPUT编号和精确选择器 |
| 实际产出 | 对象、事实字段、关系、检查或明确排除 |
| 来源身份 | 交易所原始导出、截图、获准处理表、用户逐字原话、计算结果或其他获准来源 |
| 结论状态 | 直接可证、确定推导、有界、候选、未知、不适用 |
| 适用和冲突 | 适用对象、时间范围、精度、是否冲突及冲突关系ID |
| 检查结果 | 通过、部分、阻断及证据指针 |

正式分母应保持：

- 阶段一九十三项能力；
- 阶段二新增一项候选能力；
- 合计九十四项；
- 历史状态分布为六十九项已有支持、十九项严格缺口、五项非客观边界和一项阶段二新增候选。

不得建立一百三十六乘九十四的人工大表。只有适用于具体交易或对象的能力才展开；全局、账户和边界能力只在正确粒度上出现一次或按实际对象展开。

## 9．对象识别、去重和冲突的最低规则

### 9.1 已有稳定ID优先继承

- 交易使用已冻结稳定交易ID和position_cycle_id；
- 订单保留order_id及来源记录身份；
- Fill保留source_fill_record_id、fill_reconstruction_id和交易所业务键；
- 条件委托保留已存在的条件对象稳定ID及直接或候选生成关系；
- 资金事件保留canonical_economic_event_id、统一事件ID和来源记录身份；
- 行情、技术区间、用户阶段和资金节点继承各自已有ID。

### 9.2 没有稳定ID时

只能用固定来源文件指纹、来源工作表或成员、来源行、原始业务键和规则版本生成确定ID。禁止手工临时编号后当成正式稳定ID。

### 9.3 同一对象的多份记录

- 主来源提供主值；
- 补充来源提供主来源没有的合规字段、映射或来源链；
- 验证来源只核对；
- 两个来源有差异时分别保留；
- 只有固定规则能证明哪个值适用时，才生成确定推导；
- 无法裁定时保留冲突，不得静默覆盖。

### 9.4 一对多和多对多

对象可以关联零笔、一笔或多笔主动交易。账户级资金、共享行情、跟单影响和未归属条件对象不能被迫放进单一trade_id。

### 9.5 全量构建前必须固定的可执行定义

以下内容必须作为“构建程序与规则包”的正式候选保存并通过检查，不能只写原则后交给执行者现场选择：

- 准确字段目录和数据结构定义；
- 字段和关系级组装表；
- 稳定ID的确定生成规则；
- 同秒事件的稳定排序键，以及排序不代表真实因果先后的显示规则；
- 长整数、十进制定点、时间、时区、币种、单位和规范化序列化规则；
- 冲突记录结构、冲突关系ID和适用范围表达；
- 三项重算的可执行实现；
- 构建程序、配置、代码版本、依赖锁定和运行环境清单；
- 最小测试样例、预期结果和输入身份与选择器清单。

其中任何一项仍需执行者临场决定时，不得开始全量一百三十六笔构建。

- 三百零一项原分类逐项守恒；
- 未准入旧工程、历史Chat和失败候选。

### 11.2 结构和守恒

- 136主动、12跟单、148总体关系正确；
- 所有对象ID唯一；
- 每个引用目标存在；
