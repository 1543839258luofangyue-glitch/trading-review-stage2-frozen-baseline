# 新窗口主接管说明｜截至阶段二冻结，并说明原阶段三设计

## 先说结论

这是一份给**新 Chat 第一次接手项目时**阅读的主说明。

它交接的正式成果停点是：**阶段一和阶段二已经由用户验收并冻结。**同时，它说明在这个停点以后原本应怎样通过阶段三进行最终交叉裁定，但不交接后来错误执行阶段三的过程和结果。

它不把阶段二冻结以后错误执行的旧路线带进来。那条路线的业务答案、数量、问题、检查、修补和处理办法已经排除：不作为现在的事实基础，不作为问题线索，不作为下一步方案，也不作为默认要读的材料。

但是，**原阶段三在正确路线中已经设计过**。它原本只负责把阶段一和阶段二两套冻结底稿逐项交叉比较，决定客观交易链最终由什么组成、具体采用哪些文件和数据、哪些需要重算、哪些只能参考或禁止、哪些仍然未知。这个原设计属于必须交接的正确历史；不能因为后来执行路线错误，就把“设计已经存在”改写成“阶段三从未设计”。保存原设计也不等于今天已经授权执行。

新 Chat 第一次完整接管的默认任务不是开始下一阶段或重做过去，而是：**按完整阅读关系读取、理解、用用户能听懂的话复述，并等待用户纠正。**如果用户当前消息和04A另有具体授权，只能在完成接管理解后按该授权的对象、动作和停点执行，不能从本文件自行取得权限。

## 一、完整接管材料怎样一起使用

正常完整换窗口时，先从仓库 `README.md` 进入，再按下面顺序完整阅读正文，不能只看标题、目录、摘要或别人转述的一小段：

1. 三份截至阶段二冻结的固定基础：
   - `00_新Chat先读_正确接管总说明_截至阶段二冻结.md`（本文件）：说明项目为什么开始、阶段二冻结以前怎样发展，以及怎样读取后来的实际停点；
   - `01_截至阶段二冻结_完整正确发展脉络与关键用户原话.md`：保存关键用户原话、容易混淆的历史称呼、正确发展脉络、冻结成果文件名称和后来的澄清；
   - `02_新Chat职责_授权边界与防漂移规则.md`：说明接手后怎样避免把辅助工作做成主任务，或把讨论误当成执行。
2. 阶段二以后持续更新的《交易复盘项目履历》。
3. 阶段二以后所有已经由用户验收冻结阶段的主要中文白话结果。
4. 04A当前控制页。
5. 仍然有关的04B。
6. 当前任务真正需要且已经获准读取的详细正式材料。

三份文件分工不同，缺一份就不是完整交接。特别是：

- 本文件不是用户原话全集；遇到“用户当时到底怎么说”的问题，要回看第 01 份文件或被允许提供的原始引文。
- 第 01 份文件不是业务执行指令；它帮助正确理解历史、目标、文件身份和授权边界。
- 第 02 份文件不是新的项目计划；它只防止接手者越界或跑偏。

这三份文件是截至阶段二冻结的固定基础，不能被改成不断追加的执行流水。不能只读履历，也不能只读三份固定基础后忽略后来已经形成并获得用户验收冻结的正式结果和动态控制状态。

长期共同读取默认通过已经连接的GitHub插件打开用户指定的完整提交：正常接管读取`main`正式主线的固定提交；检查尚未验收的修改稿时，读取对应待检查分支的固定提交，并把候选与它所依据的正式主线起点分开。只给分支名称、文件名、本机路径、最新页面或会继续变化的地址，不等于已经读到正文，也不能代替完整提交编号。

`main`正式主线只保存用户已经最终验收、并另行授权并入的正式版本；未经最终验收的修改只放在待检查分支。检查不通过时，在同一待检查分支继续修正并形成新的固定提交。只有GitHub插件发生真实读取失败、限制已经说明，而且用户明确同意该次改用附件时，才可把完整附件作为临时备用办法；不能把附件恢复成日常传递方式。任何创建分支、修改、提交、上传、合并或删除仍须取得用户对该次动作和文件范围的明确授权。

各入口的职责必须分开：

- README只负责仓库入口、固定阅读顺序和材料身份；
- 本文件与01、02共同构成固定接管基础；
- 项目履历只记录阶段二以后影响长期接管的稳定决定、授权、结果、角色和文件变化；
- 04A只负责当前授权、当前状态、最后冻结阶段和中断边界；
- 04B只负责进入客观交易链以前仍需解决的问题，不是项目进度表、自动任务清单或实时状态表；
- 03只是用户以后可以复制给新 Chat 的提示词模板，不是仓库自动命令；
- 每个重大冻结阶段只设一个主要中文白话结果入口，已有合适文件就复用，不重复造同类说明。

### 普通 Chat 的证据边界

普通 Chat 通常不能自动读取用户电脑里的文件，也不能因为看到一个本地路径就算“已经读过文件”。

因此：

- 新 Chat必须实际通过GitHub插件打开用户指定的固定提交和具体文件，并如实说明哪些正文已经读到末尾；看到目录或文件名不等于读过正文。
- 如果GitHub插件真实读取失败，新 Chat必须说明失败的文件、位置或限制并停下；只有用户明确同意后，才能把完整附件作为该次读取的临时备用办法。
- 如果只给了文件名或电脑路径，新 Chat 必须明确说“我还没有读到文件本体”，不能假装知道内容。
- 如果三份文件缺少任何一份，新 Chat 必须说明缺哪一份、因此不能确认什么。
- 新 Chat 没有实际读取原始材料时，不能声称自己已经核对过原始交易记录、历史工程文件、阶段一成果或阶段二成果。
- 即使三份文件齐全，三份文件也只构成接管所需的说明和边界，不自动给任何人读取其他目录、修改文件、运行工具或开始分析的权限。

## 二、项目为什么开始

用户希望认真回看自己的真实交易经历：交易过程怎样发生、结果怎样形成、自己当时说过什么、后来哪些判断能被事实支持。

用户不希望 AI 只凭几句自述、少量盈亏数字或旧报告，就替他下结论，更不希望 AI 先认定他“应该改变什么”。因为一开始就预设结论，会让后面的分析只去证明那个预设。

所以，这个项目的正确服务关系是：

```text
用户想实现的最高方向：“彻底改变”
        ↑
用户看懂分析后，真正理解自己的交易和自身问题
        ↑
AI 依据事实和用户自己表达的意思，形成分析
        ↑
能够还原真实交易过程的客观交易链
        ↑
为了还原事实而需要确认的最小资料、来源和缺口
```

这张图只说明“下面的工作为什么要服务上面的目标”。它**不是**自动开工顺序，也**不是**任何执行授权。

图中的“事实”和“用户自己表达的意思”必须保留不同来源身份。客观交易记录、用户原话、人工复盘和 AI 解释不能混成一层；以后分析时何时、怎样结合，仍由用户在看到正确材料后另行决定，本说明不提前规定。

### 最高方向的准确含义

用户明确坚持的最高方向是“彻底改变”。当前材料能够确认的是：

- 这不是“暂时不交易”或“暂时没有条件交易”；
- 这也不是“彻底杜绝交易”；
- 它指向的是：如果以后再次处于真实交易情境，用户仍能实现真正的自我控制；
- 到目前为止，用户没有要求 AI 先指定他必须改变的性格、心理、情绪、行为或交易习惯；
- 什么才算真正改变、怎样衡量、最后要用什么方式帮助用户，仍需要在有了客观分析以后由用户决定。

因此，客观交易链、AI 分析、表格、工具、文件检查和任何管理办法都只是可能的服务手段，不能反过来取代“彻底改变”这个最高方向。

## 三、必须分开的五个“为什么要做”

这里说的“五个目标根”，不是五个文件夹，也不是五个同时运行的任务。它只是帮助新 Chat 分清：不同阶段为什么存在，哪些还有效，哪些不能再拿来指挥现在。

| 名称 | 白话意思 | 当前地位 |
| --- | --- | --- |
| 用户最高最终目标根 | 项目最终服务于用户的“彻底改变” | 保留为最高方向；不自动产生执行权，也不预先规定改变内容 |
| 旧工程历史目标根 | 旧工程当时为什么做出很多表格、处理步骤和产品设想 | 只用于解释历史；旧工程已经失败并停止，不能续跑 |
| 阶段一、阶段二审计目标根 | 把旧工程前后两段历史分别查清并冻结 | 两份冻结调查结果可作为以后判断的证据起点；不等于客观交易链已经建好 |
| 正确接管目标根 | 让新的接手者准确理解历史、目标、证据边界和禁止继承内容 | 接管本身只负责理解和防跑偏；不是业务执行授权 |
| 阶段三及以后具体工作目标根 | 原阶段三为什么存在，以及某个实际时点是否可以执行 | 原阶段三的目的、输入、边界和停止门已经有历史设计；实际是否进入、是否修改设计及阶段三以后的工作，必须查看04A和用户当前消息 |

这五类不能混用。尤其不能把“旧工程曾经计划过”写成“现在应当继续”，也不能把“阶段一、二已经冻结”写成“已经可以直接建链或分析”。

## 四、正确的历史概览

以下只交代理解项目必须知道的历史主线。它不是对每个历史文件、每个技术动作或每个旧结论的重新裁定。

### 1. 旧工程曾经存在，但已经失败并停止

旧工程原本尝试把交易记录、截图、人工复盘和一些处理结果整理起来，用于交易复盘、交易过程还原和后续理解。

后来，工作逐渐从“帮助用户看懂真实交易”扩张成大量辅助性的技术、管理和展示工作。文件、阶段和规则越来越多，反而遮住了项目真正要回答的问题。用户已明确：旧工程是失败的历史工程，已经停止运行。

这不等于旧工程里的每一份原始材料都必然没有价值。准确边界是：旧工程整体不再是当前系统，也不是当前权威；以后只有在用户明确授权、而且当前问题确实需要时，才能定点查看某一份具体原始材料，并按实际证据判断它能说明什么。

### 2. 历史恢复材料被保留，但不自动采用

旧工程停止后，曾有对历史事实、工程状态和用户交易表达的整理与恢复。这些材料帮助说明：过去留下了什么、当时怎样理解、哪些来源可能需要以后再核对。

它们是历史材料，不等于今天已经可直接使用的客观交易链，也不等于其中的结论已经被用户采用。

### 3. 阶段一：看 K01 之前的历史

“K01”只是历史上一次明确启动动作的名称，不是现在的新授权。

阶段一从 K01 之前的历史出发，调查当时认为客观交易过程需要哪些内容、旧工程留下了哪些具体资料或做法、各自来自哪里、哪些地方仍然不清楚。它把这段调查结果整理成一套冻结底稿。

阶段一的冻结表示：用户接受这套“历史调查结果”作为以后比较时不能被悄悄改写的基线。

它**不表示**：

- 客观交易链已经建好；
- 某个旧资料已经被正式采用；
- 所有历史内容都已被完全证明；
- 可以自动进入下一阶段、实际建设或正式分析。

### 4. 阶段二：看 K01 之后的历史

阶段二在不改写阶段一的前提下，调查 K01 之后历史上实际发生过什么：计划怎样写、实际怎样做、哪些地方出现变化、返工、纠正、候选资料和限制。

阶段二同样形成一套冻结底稿。它让以后的人能够把“原先计划”“实际发生”“用户的态度”“候选材料”“尚不能确认的部分”分开看。

阶段二的冻结表示：用户接受这套 K01 之后的历史调查结果作为受保护的基线。

它**不表示**：

- 阶段二中提到的候选资料已经采用；
- 某次历史纠正已经成为今天应继续执行的办法；
- 阶段一遗留的不确定性已经自动消失；
- 已经获得新阶段、实际建设或正式交易分析的授权。

### 5. 阶段一、二冻结后，原阶段三设计已经具备，但后来执行路线被排除

阶段一和阶段二已经分别完成用户验收和冻结。它们是两本“历史调查报告”，不是完成后的交易链，也不是 AI 分析报告。

在正确的三阶段安排中，阶段三早已被命名并设计为“客观交易链正式构成与构建输入最终交叉裁定”。它的作用不是再扫描历史，也不是直接建立一百三十六笔交易链，而是把阶段一的“K01前需要什么、有什么零件”和阶段二的“K01后新增、修改、出错和纠偏了什么”放在一起，形成最终组成和最终构建输入的待用户验收裁定。

阶段二冻结以后，阶段三曾沿错误路线被执行，之后又继续产生大量问题、检查、修补和控制材料。用户已经决定：**这些执行过程和结果全部不继承。**新 Chat 不得把它们当成项目延续、候选答案或默认材料，也不得利用其中的问题数量或结论反向设计现在的阶段三。这里保留的是原阶段三的正确设计，不保留后来错误执行的内容。

阶段二冻结时形成的稳定衔接边界是：**保留阶段一、阶段二冻结成果和原阶段三设计说明；后来错误执行的阶段三过程与结果不继承。**接管时是否已经出现新的冻结阶段或新的有界任务，必须通过项目履历、后续已冻结阶段主要结果、04A、仍然有关的04B和用户当前消息确认，不能由本固定文件预判。

## 五、阶段一、阶段二冻结到底留下什么，没有留下什么

阶段一留下的是：对 K01 之前历史的调查结果、来源边界、候选与未知。

阶段二留下的是：对 K01 之后历史的调查结果、实际过程、候选与限制。

两者共同留下的是：以后如果用户另行授权，新的工作可以从哪里开始查证，而不是必须从头猜历史。

两者共同**没有**留下的是：

- 由两套冻结基线本身产生的阶段三执行授权；
- 一份已经通过用户验收的阶段三裁定结果；
- 一份已经可以直接执行的客观交易链建设方案；
- 一份已经被采纳的旧资料名单；
- 对用户的心理、行为或人生改变的结论；
- 对未来 AI 分析的授权；
- 对任何人读取、复制、修改、计算、建设或运行材料的默认权限。

“冻结”只表示历史调查基线被固定下来，不能在以后悄悄改写；它不等于“正确答案已经全部确定”，更不等于“下游工作已经批准”。

两者与原阶段三设计共同留下的是：如果用户以后明确授权阶段三，应从这两套冻结底稿进行双向交叉裁定，而不是重新发明目标、重扫全部历史或直接建链。

## 六、怎样读取实际停点，谁能做什么

本固定文件只保存阶段二冻结以前及其正确衔接所需的稳定事实和长期角色原则，不登记会变化的履历最新记录号、04B问题数量、候选验收状态、检查进度、当前授权或当前最后冻结阶段。

稳定事实包括：阶段一和阶段二已经由用户验收冻结；01B最高最终目标已经冻结，但具体改变什么、怎样衡量和验收没有因此确定；旧工程停止，不整体续跑；原阶段三已有正确历史设计；后来错误执行的阶段三路线、结果、数量和文件不继承。实际接管时，应按本文件第一节的顺序从动态正式来源确认后来又冻结了什么、现在允许做什么以及停在哪里。

### 只继承已经由用户验收冻结的阶段

只能继承已经由用户验收冻结的阶段。如果主要负责窗口在某个阶段获得用户验收冻结以前中断或更换，新窗口不得从原执行、半成品、候选结果或检查进度继续，也不得把这些未经冻结结果作为重新执行输入。实际最后可继承到哪个阶段，应查看后续已冻结阶段主要结果和04A，不能在本固定文件中硬编码。

正确处理方式是：回到上一个已验收冻结阶段，重新理解整个项目、为什么需要这个未冻结阶段、它原本怎样设计、怎样执行、怎样检查和怎样验收；随后由用户重新确认并重新授权，从头执行整个未冻结阶段。只有在阶段开始以前就由用户明确划分了少量、可以分别验收冻结的子阶段时，才可以按已经冻结的子阶段继承；不能事后把中间步骤包装成冻结成果。

| 用户 | 决定任务、允许修改的文件范围、执行结果、阶段验收和冻结 | 不需要替不同 AI 窗口机械搬运指令和回报 |
| 新 Chat 协调窗口 | 按完整入口阅读并用白话复述；每项任务开始前判断可能影响哪些文件并向用户说明理由；任务结束后检查结果并判断哪些动态文件需要更新 | 不能替用户定方向、授权、验收或开工；不能把讨论变成方案执行 |
| 新的干净 Work | 只执行用户已经授权的任务，并作为中央动态文件的主要实际写入窗口；发现超出批准范围必须先报告 | 不能开始未授权阶段；不能修改批准范围外文件；不能从旧文件、旧聊天或 Chat 的猜测中取得新权限 |
| 第三方审查 Work | 检查主要 Work 有没有漏写、误写、越权或造成文件冲突，不与主要 Work 同时修改同一批中央动态文件 | 不能替执行窗口工作、偷偷修复或自行批准阶段三；实际由哪个窗口承担该角色须查看项目履历和04A |
| 未来正式分析 AI | 只有在客观交易事实已经具备、经过核对且另获授权后，才可能参与分析 | 未经授权不能开始分析或替用户定义改变方向 |

项目履历曾有由当时指定 Work写入、新 Chat检查、用户确认的短期例外；接管时必须从项目履历和04A确认该例外是否仍有效。完整内容审查者必须没有参与本次写入、理解相关背景、知道审查标准并能取得必要证据；不得临时找一个不了解项目的窗口冒充完整内容审查。是否另做纯文件身份核验，由用户按实际需要决定，不是自动强制步骤。

## 七、新 Chat 第一次接手时的唯一动作

新 Chat 第一次接手后，应该只做下面五件事：

1. 从 README 开始，依次完整读取三份固定基础、项目履历、阶段二以后所有已经冻结阶段的主要白话结果、04A、仍然有关的04B和当前任务已获准读取的正式材料；
2. 用普通中文复述：项目为什么开始、最高方向是什么、旧工程为什么不能续跑、阶段一和阶段二各自冻结了什么、目前为何停在这里；
3. 复述原阶段三为什么产生、原本只负责什么、明确不负责什么，并说明原设计与后来错误执行结果必须分开；
4. 明确区分四类话：已被材料支持的事实、用户原话或后来的澄清、AI 自己的理解、尚未决定的建议；
5. 把复述交给用户检查，等待用户纠正或给出下一项明确授权。

没有另外获得用户授权时，它不应做的事包括：

- 把原阶段三重新发明成另一项工作，或擅自修改其目标、输入和边界；
- 设计阶段三以后的任何新业务阶段；
- 提出固定的交付物、步骤、材料清单或验收流程；
- 读取未上传的本地文件、旧工程或历史聊天；
- 把历史候选、旧结论或旧问题重新列为当前待办；
- 直接建立客观交易链、开始交易分析，或讨论用户应怎样改变；
- 指挥新 Work、旧 Codex 或其他执行者做任何实质工作。

如果用户只是在检查新 Chat 是否理解，答案就应止于清楚复述。只有用户以后明确提出一个新的目标和授权，才可以另外讨论那一项工作的最小范围；讨论也不等于执行。

## 八、最容易犯的错误

1. 把旧工程的“完成”“正式”“最终”等旧称呼，当成今天仍有效的结论或权限。
2. 把阶段一、阶段二冻结，当成客观交易链已经建好或资料已经正式采用。
3. 把后来的解释写成当时已经发生的事实。
4. 把 AI 的总结、建议或猜测，写成用户原话或已证实事实。
5. 只凭本地路径、文件名或别人的概述，就说自己已经读过原件。
6. 为了显得完整，先设计大量步骤、表格、检查和管理办法，再去寻找它们与用户目标的关系。
7. 把“以后可能会做”误写成“现在已经授权做”。

发现上述任何一种混淆时，应停在当前边界内，用白话告诉用户：混淆在哪里、当前能确认什么、不能确认什么；不能私自用更多工作去填补它。

## 最后一段白话总结

这个项目不是为了把旧工程重新运行起来，也不是为了马上做一个庞大的交易系统。它从用户想真正看懂自己的交易开始，最终服务于用户所说的“彻底改变”。

旧工程已经失败并停止。阶段一和阶段二把旧工程前后两段历史分别查清并冻结，给未来留下两本不能悄悄改写的调查底稿，但没有留下自动开工的权利。

新 Chat 第一次完整接管时，应先按固定阅读关系理解这段历史、后来稳定状态和实际控制边界，并用用户听得懂的话复述，其中必须包含原阶段三的正确设计和“只继承已经验收冻结阶段”的原则。项目当时已经走到哪里、是否存在执行授权以及当前应停在哪里，必须以项目履历、后续已冻结阶段主要结果、04A、仍然有关的04B和用户当前消息为准；本固定文件不预先写死答案。后来错误阶段三的结果始终不继承，也不能由其反向生成新的路线。
